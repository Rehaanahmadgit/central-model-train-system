# Architecture (as built)

Long spec: `doc/03_ARCHITECTURE.md`, `doc/04_STORAGE_LAYOUT.md`. This file lists what exists in code.

- **Backend** `backend/app` (FastAPI, py3.12): `api/` routers (projects, datasets, uploads, verifications, runs, models, checkpoints, licences, system, health), `services/`, `storage/` (atomic writes, JSONL, locks, recovery), `realtime/` (broadcaster + WS with `seq` resume), `core/` (config, auth token middleware, device, doctor).
- **Verification** `verification/`: runner + `checks/*` (24 checks, `VERIFIER_VERSION` 1.2.0 = cache key), `manifest.py` (parquet), `recommend.py` (hparam + checkpoint recommendation).
- **Checkpoints** `checkpoints/`: `default_catalog.yaml` (+ override in volume), `catalog.py`, `licences.py` (acceptance record `<home>/licences/accepted.json`), `resolver.py` (licence gate → FileLock → disk preflight → `.part` resume → sha256 → atomic move → `index.json`).
- **Auto-select** (`verification/recommend.py`): `rank_checkpoints` flags each entry `eligible` / `rejected` / `warnings`; `auto_select` returns the top eligible id + reason; both stored in `report.json` `derived` (`auto_selected`, `auto_select_reason`). `DeviceInfo.memory_gb` supplies GPU VRAM.
- **Run start**: `services/runs.create_run` refuses unaccepted licences (409) and frozen-backbone-without-weights (400). `JobManager` resolves the checkpoint while the run is `preparing` and writes `run.json` `waiting_for` (`resolving|waiting_lock|downloading`, percent); resolver failures end the run `failed` with the exact code (`CHECKPOINT_OFFLINE|PARTIAL|SHA_MISMATCH|DISK_FULL|DOWNLOAD_FAILED`, `LICENCE_NOT_ACCEPTED`) plus `failure.catalog_id`/`can_import`.
- **Import from file**: `PUT /api/v1/checkpoints/{id}/import` (raw body) → sha256 verified → store; `.part` file is `checkpoints/.tmp/<id>.<sha16>.part` and survives failures so the next attempt resumes.
- **Training** `training/`: `job_manager.py` spawns `worker_main` subprocess per run (own process group, heartbeat); `engine.py` shared `TrainEngine`/`EngineHooks`; plugins `rtdetr.py`, `cnn.py`, `random_forest.py`; registry row per plugin.
- **Auth** (`core/auth.py`, `main.py` middleware, `cli.py`): token resolved at startup (env > `<home>/access-token` > generated, 0600); `verify_token` fails closed; 401 codes `ACCESS_TOKEN_REQUIRED` / `ACCESS_TOKEN_INVALID`; `TRAINHUB_AUTH_DISABLED` is the only way open. `trainhub --reset-token` rewrites the file (restart to load). Frontend: `lib/api.ts` raises `trainhub:auth`, `components/TokenPrompt.tsx` shows the prompt.
- **Limits/SSRF**: `api/uploads.py` caps each chunk (413 `CHUNK_TOO_LARGE`), `services/uploads.py` 413 `UPLOAD_TOO_LARGE`; `resolver.validate_source_url` + `_GuardedRedirects` (https only, public IPs only, ≤3 redirects) → `CHECKPOINT_SOURCE_BLOCKED`. `catalog.load_catalog` merges override field-wise.
- **Device probe**: `core/device.probe_device` resolves the device in a cached subprocess; `/api/v1/system` `gpu` = `{available, name, memory_gb, message}` from it. The API process never imports torch (forking the verification pool after a torch import hung Verify). Configure shows `lib/device.deviceNotice`.
- **Frontend** `frontend/src` (React + TS + Vite + Tailwind): Wizard (Dataset, Model, Verify, Configure, Train), LiveRun, CheckpointsPage, `LicenceCard`, `CheckList`.
- **Storage**: files only under `TRAINHUB_HOME` (`/data` in the image): datasets, runs, checkpoints/store + index.json, licences/accepted.json, cache/verif.
- **Tooling**: `make verify` (ruff + mypy + fast pytest + frontend build); Playwright e2e in `frontend/e2e`.
