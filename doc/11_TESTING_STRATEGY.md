# 11 — Testing Strategy

## 1. Test pyramid
- **Unit (majority):** verification checks, checkpoint selection scoring, resolver logic (with fake storage/HTTP), state machine transitions, config validation, schema forms.
- **Integration:** API + real filesystem workspace (temp dir/volume): upload → verification → run creation; real subprocess training with a tiny model; WebSocket stream and resume tests. No database or external services needed.
- **End-to-end:** Playwright flows (upload → verify → train → live dashboard → evaluation) on a tiny dataset with a tiny model (runs in < 2 min on CPU).
- **Non-functional:** load, chaos, security.

## 2. Fixtures: synthetic datasets (generated by script, committed as generator, not binaries)
Create a `tests/fixtures/make_datasets.py` that builds small datasets:
- `good_cls`, `good_yolo`, `good_coco`, `good_csv`
- Broken variants: corrupt image, missing labels, label out of range, bbox out of bounds, duplicate images across train/val (leakage), single-class, severe imbalance, empty dataset, wrong format, zip with `../` path, zip bomb sample (tiny but high ratio), CSV with missing target.
Each broken dataset has an **expected verification outcome** in a table; tests assert it.

## 3. Critical test cases
**Verification**
- Each check detects its seeded defect and does not false-positive on good data.
- Cache hit for identical dataset + verifier_version; miss after change.
- Streaming progress events emitted in order.

**Checkpoints**
- Local hit → no download call (assert mock not called).
- Corrupt local file → re-download, sha mismatch handled.
- Two concurrent resolvers → exactly one download.
- Partial download never visible in registry; resume works after interrupt.
- Disk-full preflight failure message.

**Training**
- State machine: valid/invalid transitions.
- Pause/resume/stop honoured at batch boundary; resume restores exact epoch/optimizer state.
- Worker subprocess killed → run `failed(worker_lost)`, API alive.
- NaN loss triggers stop with reason.
- OOM simulation triggers batch-size reduction (when enabled).
- Metrics order and `seq` monotonic; reconnect with `last_seq` replays missed events.

**Security**
- Path traversal via IDs/parameters (`../`) is rejected; nothing resolves outside `TRAINHUB_HOME`.
- Path traversal archives rejected; oversize rejected.
- Optional access token enforced (constant-time compare); no token configured = open.
- Audit files get entries for all state changes and contain no personal data. **Privacy grep test:** after a full run, scan the whole workspace and logs for email/IP patterns and `User-Agent` strings → zero matches.

**Reproducibility**
- Same seed + config + dataset hash → metrics within tolerance on CPU tiny model.

## 3b. Storage / crash-safety tests (critical because there is no database)
- Atomic write interrupted (kill between tmp write and replace) → old file intact, no partial file visible.
- JSONL with truncated last line → loader repairs the tail, `seq` continues correctly.
- Two processes writing the same run → per-run lock prevents interleaving.
- `kill -9` API during `running` → on restart run is `interrupted`, `queued` runs re-queued, `.part` leftovers cleaned.
- Corrupt `run.json` → quarantined to `*.corrupt`, system health shows a warning, other runs unaffected.
- Dataset delete while a run uses it → 409.
- Index rebuild from files yields identical listings.

## 4. Quality gates (CI)
- Unit + integration must pass; coverage ≥ 80% on `verification/`, `checkpoints/`, `training/` core.
- Lint/type-check clean; no high-severity vulnerabilities.
- E2E smoke on main branch and before release.

## 5. Performance tests
- Verify 10k-image dataset: < 2 min on reference hardware.
- 50 concurrent WebSocket clients on one run: latency < 1 s p95.
- Metrics query for 1M rows: downsampled response < 500 ms.

## 6. Chaos / failure drills
Kill the training subprocess, `kill -9` the API during training, power-cut simulation, drop network during download, fill disk, truncate the last line of a JSONL file. Expected: no data loss, clear run states, auto-recovery where designed.

## 7. Manual QA checklist
Browser refresh mid-training; two tabs same run; closing laptop and returning; very long logs; slow network; large file upload pause/resume.
